# deeval

![JavaScript](https://img.shields.io/badge/JavaScript-ES_Modules-F7DF1E?logo=javascript&logoColor=white) ![Node.js](https://img.shields.io/badge/Node.js-18%2B-5FA04E?logo=nodedotjs&logoColor=white) ![semver](https://img.shields.io/badge/semver-7.8-CB3837?logo=npm&logoColor=white) ![YAML](https://img.shields.io/badge/yaml-2.9-CB171E?logo=yaml&logoColor=white)

deeval is a command-line tool that inspects a Node.js or Bun project. It checks the runtime version, compares `package.json` with the lockfile and the lockfile with `node_modules`, and ends with a list of suggested actions.

deeval is read-only. It never installs packages, edits files or runs project scripts.

**npm:** [@mete-sirin/deeval](https://www.npmjs.com/package/@mete-sirin/deeval)

## Features

- Checks the installed Node.js against `engines.node`, `.nvmrc` and `.node-version`, and the installed Bun against `engines.bun`
- Detects the package manager from the `packageManager` field or the lockfile, and warns about multiple or mismatching lockfiles
- Compares `dependencies`, `devDependencies` and `optionalDependencies` with the lockfile in both directions: missing entries, stale entries, changed specifiers and locked versions outside the declared range
- Compares the lockfile with the packages installed in `node_modules`
- Groups findings by severity and lists each suggested fix once, using your package manager's commands
- Uses npm's `semver` package for all range checks, so `^`, `~`, `||`, `>=18 <22`, x-ranges and prereleases behave as they do in npm

## Getting Started

You need Node.js 18 or newer.

Run deeval in the root directory of the project you want to check, where its `package.json` is:

```bash
npx @mete-sirin/deeval
# or
pnpm dlx @mete-sirin/deeval
bunx @mete-sirin/deeval
```

Or install it globally:

```bash
npm install -g @mete-sirin/deeval
deeval
```

The package is published under the `@mete-sirin` scope, but the command it installs is `deeval`. deeval inspects the current directory and takes no arguments. `deeval --help` prints usage and `deeval --version` prints the version.

Example output for a project whose lockfile is out of date:

```
deeval: project inspection

Project: /home/you/my-app
Runtime: Node.js
Package manager: pnpm (pnpm-lock.yaml)

[OK]    Node.js 24.21.0 satisfies >=18 (engines.node).
[WARN]  yaml is declared as ^3.0.0 in package.json but locked as ^2.9.1 in pnpm-lock.yaml.
[WARN]  No node_modules directory, so dependencies are not installed.
[ERROR] yaml is locked at 2.9.1, which does not satisfy ^3.0.0.
[ERROR] zod is in package.json but missing from pnpm-lock.yaml.

Summary: 2 errors, 2 warnings

Suggested actions:
1. Run `pnpm install` to sync pnpm-lock.yaml and node_modules with package.json.
```

### Severity and exit codes

| Label | Meaning |
| --- | --- |
| `ERROR` | A confirmed problem, such as a dependency missing from the lockfile |
| `WARN` | A likely problem, such as a stale lockfile entry or a missing devDependency |
| `INFO` | Something deeval could not check, such as a `workspace:*` specifier |
| `OK` | A check that passed |

| Exit code | Meaning |
| --- | --- |
| `0` | No errors (warnings are allowed) |
| `1` | At least one error |
| `2` | No `package.json` in the current directory, or an unknown option |

### Supported projects

| | Supported | Reported as unsupported |
| --- | --- | --- |
| Runtimes | Node.js, Bun | |
| npm | `package-lock.json` and `npm-shrinkwrap.json`, lockfile version 2 and 3 | lockfile version 1 |
| pnpm | `pnpm-lock.yaml`, lockfile version 6 to 9 | older versions |
| Yarn | Yarn 2 and newer (Berry) | Yarn classic (v1) |
| Bun | text `bun.lock` | binary `bun.lockb` |

A Bun project is one with a Bun lockfile, a `packageManager` field naming Bun, or an `engines.bun` field.

With Yarn Plug'n'Play there is no `node_modules`, so the install check is skipped.

### Not checked

- Workspaces and monorepos: only the root package is inspected. In a monorepo, run deeval in each package directory.
- `peerDependencies` and transitive dependencies
- The version of the package manager itself
- Deno and other languages

## Development

The repository uses pnpm.

```bash
pnpm install
pnpm start       # run deeval on this repository
pnpm test        # node:test suite, including end-to-end runs against test/fixtures
pnpm typecheck   # TypeScript checks of the plain JavaScript (checkJs)
```

The lockfiles in `test/fixtures/*-basic` were generated by the real npm, pnpm, Yarn and Bun.

To release a new version, bump `version` in `package.json`, merge it into `master`, then run `pnpm publish` from `master`. The `prepublishOnly` script runs the tests and the type check first. Use pnpm, because the `devEngines` field in `package.json` makes `npm publish` fail in this repository.
